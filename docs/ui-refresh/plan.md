# UI refresh implementation plan

This focused pass brings the native app closer to the available Ridr screen mockup and the Day 2 design specification. It does not change the agreed feature scope or count as Day 26–30 acceptance work.

1. Align shared spacing, typography, cards, and buttons with the native-friendly Day 2 tokens; make the home screen's ride actions easy to find.
2. Improve the create, join, rides, and history screens using the data and actions they actually support. Keep the ten-character invite code, invitation preview, and one-contact rule.
3. Put the live group map near the top of the active ride while retaining SOS, warning, messaging, and management actions.
4. Check type safety, existing mobile tests, exported build, and the connected Android app. Record any remaining visual or device limitations honestly.

The older raster screens are illustrative. Scheduled ride fields, extra emergency contacts, and automatic crash prompts are outside the released feature scope and are not added as decorative controls.
