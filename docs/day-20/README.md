# Day 20 — private status sharing

An active member who has turned on location sharing can choose a one-, four-, eight- or 24-hour bearer link from **Share my status** on the ride screen. The URL is available only on that creation screen and can be shared through the phone's share sheet. The server stores a SHA-256 token hash, not the bearer token. Retrying a creation key returns link metadata without recovering the URL; the owner can revoke that link and create another. Only the owner's links are listed or revocable from their account.

`GET /v1/status#<token>` serves an account-free browser page. The fragment is removed from browser history before the first request; the token is sent only in the `Authorization` header to `GET /v1/public/status`. Every read checks the active ride, owner membership and account, current sharing consent, link revocation and absolute expiry. The response has only the owner's display name, last independently shared position with recording time and accuracy, own SOS state, and lease/expiry times. The page has no write controls, third-party scripts, map, group members, route, chat, contacts or history. It clears displayed data on failed renewal, rejection, visibility change or lease expiry; the lease is at most 15 seconds and never extends past link expiry. Previously seen content or a screenshot cannot be erased from a recipient's memory.

Revocation is saved on the owner's device before a network attempt. If delivery is uncertain, the screen says **Revocation pending — link may still work** and retries when reopened or foregrounded. Stopping location sharing, leaving and ending the ride also revoke links in the existing server lifecycle transactions. An offline stop/end attempt does not claim immediate server revocation.

`STATUS_VIEWER_ORIGIN` must be an origin serving the same API's `/v1/status` and `/v1/public/status` routes. Production requires HTTPS and a reachable public origin. The development default is `http://127.0.0.1:3000`, which works only on that computer and is not a recipient-ready external URL. The API sends `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, a restrictive CSP and no token-bearing log fields.

Local verification passed: the status-link database/API integration test (owner-only position and SOS projection, retry, tampering, cross-owner revoke, stop-sharing, leave, expiry, ended ride and public HTTP response); 25 existing ride lifecycle integration cases; 32-table/25-case database checks; 44 API tests; 100 mobile tests; lint and type checks; and Android, iOS and web export. A live externally reachable HTTPS deployment, recipient browser/device behavior, offline revocation on a physical phone and the Day 20 release checkpoint have not been measured. Earlier Day 15 recovery and Day 19 SOS device timing gates also remain open. The conditional crash detector remains off and its Day 33 gate is not claimed.
